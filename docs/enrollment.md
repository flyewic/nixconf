# Device Enrollment Guide

Step-by-step guide for deploying this NixOS config to a new machine from
scratch. Written from hard-won experience.

## Fast path (recommended)

After cloning the repo and installing the minimal NixOS:

```bash
cd nixconf
sudo nix-shell -p git              # if git isn't available yet (first boot after nixos-install)
```

Every step — hardware config, sops keys, flake lock — is automated:

```bash
just enroll laptop     # or desktop, or any host name
```

Then add secrets and switch:

```bash
sops secrets/secrets.yaml          # add your password hash (mkpasswd -m sha-512)
sudo nixos-rebuild switch --flake .#laptop
```

From then on: `just switch`.

`just enroll` does three things:
1. Runs `nixos-generate-config` and wraps it in the flake-parts module format
2. Creates `~/.config/sops/age/keys.txt` from your SSH key, fills in `.sops.yaml`, creates an encrypted `secrets/secrets.yaml`
3. Runs `nix flake lock`

## Manual enrollment (reference)

The steps below are what `just enroll` automates. Read them if something
goes wrong or you want to understand each step.

## Prerequisites

- NixOS installer USB (https://nixos.org/download.html)
- Internet connection
- SSH key (for sops encryption and git access)
- The config repository cloned locally

## 1. Install NixOS (Minimal)

Boot from the NixOS installer and perform a minimal installation:

```bash
# Partition disks as needed (adjust device names)
parted /dev/sda -- mklabel gpt
parted /dev/sda -- mkpart ESP fat32 1MiB 512MiB
parted /dev/sda -- mkpart primary linux-swap 512MiB 2GiB
parted /dev/sda -- mkpart primary ext4 2GiB 100%

# Format
mkfs.fat -F 32 -n boot /dev/sda1
mkswap -L swap /dev/sda2
mkfs.ext4 -L nixos /dev/sda3

# Mount
mount /dev/disk/by-label/nixos /mnt
mkdir -p /mnt/boot
mount /dev/disk/by-label/boot /mnt/boot
swapon /dev/sda2

# Generate initial config + install
nixos-generate-config --root /mnt
nixos-install
```

Reboot into the minimal NixOS installation.

## 2. Clone the Config

```bash
nix-shell -p git

cd ~
git clone git@github.com:flyewic/nixconf.git
cd nixconf          # ← repo IS the flake root; flake.nix is right here
```

## 3. Generate and Wrap the Hardware Configuration

`nixos-generate-config` outputs a plain NixOS module, but our config needs
it wrapped as a flake-parts module that exports `flake.nixosModules.<host>Hardware`.

**Step 1: generate the raw output:**

```bash
sudo nixos-generate-config --show-hardware-config > /tmp/hw.nix
```

**Step 2: wrap it and save.** The generated file starts like:
```nix
{ config, lib, pkgs, modulesPath, ... }:
{
  imports = ...
  boot.initrd.availableKernelModules = ...
  fileSystems."/" = ...
  ...
}
```

Wrap it so the final `modules/hosts/<host>/hardware-configuration.nix` looks like:

```nix
# Generated by nixos-generate-config — do not edit by hand
{ self, ... }:
{
  flake.nixosModules.<host>Hardware =
    { config, lib, pkgs, modulesPath, ... }:
    {
      # ── paste the entire generated content here ──
      imports = [ (modulesPath + "/installer/scan/not-detected.nix") ];
      nixpkgs.hostPlatform = "x86_64-linux";
      fileSystems."/" = { device = "/dev/disk/by-label/nixos"; fsType = "ext4"; };
      boot.initrd.availableKernelModules = [ "nvme" "xhci_pci" ... ];
      # ... rest of generated output
    };
}
```

Replace `<host>` with `desktop`, `laptop`, or whatever the host folder is
named. The `nixpkgs.hostPlatform` line is **required** — our `nixosSystem`
calls omit the `system` argument and rely on `hostPlatform` being set here
instead.

## 4. Configure Host Settings

Edit `modules/hosts/<host>/configuration.nix` — adjust the subscription
list if needed:

```nix
{ self, ... }:
{
  flake.nixosModules.<host>Configuration =
    { pkgs, ... }:
    {
      imports = with self.nixosModules; [
        core development niri librewolf discord <host>Hardware
      ];

      networking.hostName = "<host>";
      system.stateVersion = "26.05";
    };
}
```

## 5. Set Up Sops (Secrets Management)

### 5.1 Install the tools

```bash
nix-shell -p sops age ssh-to-age
```

### 5.2 Create your age identity file

sops needs your **private** age key to edit and re-encrypt secrets.
Derive it from your SSH key:

```bash
mkdir -p ~/.config/sops/age
ssh-to-age -private-key -i ~/.ssh/id_ed25519 > ~/.config/sops/age/keys.txt
chmod 600 ~/.config/sops/age/keys.txt
```

If `-private-key -i` isn't supported by your `ssh-to-age` version, use:
```bash
ssh-to-age -private-key < ~/.ssh/id_ed25519 > ~/.config/sops/age/keys.txt
```

If you don't have an SSH key yet:
```bash
ssh-keygen -t ed25519 -C "flyewic@gmail.com"
```

### 5.3 Update .sops.yaml

Get your **public** age key and paste it into `.sops.yaml`:

```bash
ssh-to-age < ~/.ssh/id_ed25519.pub
# → age1xxxxx...
```

Edit `.sops.yaml` — replace the `age1_REPLACE_ME` under `&admin` with your
key. Leave the host sections commented out for now (you'll add them after
each machine is running).

### 5.4 Create and encrypt the secrets file

```bash
# The placeholder in the repo is plaintext — sops can't convert it.
# Delete it and let sops create a fresh encrypted file:
rm secrets/secrets.yaml
sops secrets/secrets.yaml
```

This opens your `$EDITOR`. Add secrets in YAML format, e.g.:

```yaml
# User password hash (generate with mkpasswd -m sha-512)
user-password: CHANGE_ME
```

Generate your password hash:
```bash
mkpasswd -m sha-512
# Type your password, copy the long string starting with $6$...
```

Paste that hash in place of `CHANGE_ME`, save and quit. The file is now
encrypted with your admin key.

### 5.5 Add host keys later

After the machine is running and sshd has started (host keys are generated):

```bash
# On the machine:
ssh-to-age < /etc/ssh/ssh_host_ed25519_key.pub
# → age1yyyyy...
```

Add this key to `.sops.yaml` under `&laptop` (or `&desktop`), uncomment
the anchor, and add it to the creation rule. Then:

```bash
sops updatekeys secrets/secrets.yaml
```

This decrypts with your admin private key and re-encrypts for all
recipients including the new host.

## 6. Set Timezone and Locale

Already set in `modules/collections/core.nix`. Defaults:
- `time.timeZone = "Europe/Stockholm"`
- `i18n.defaultLocale = "en_US.UTF-8"`
- `console.keyMap = "us"`

Change if needed.

## 7. First Rebuild

NixOS installs with flakes disabled. Bootstrap them for this session:

```bash
# Lock the flake (downloads dependencies)
nix --extra-experimental-features 'nix-command flakes' flake lock

# Build and switch to your configuration
sudo nixos-rebuild switch --flake .#<host>
```

After this first switch, your config's `core` module enables
`nix.settings.experimental-features = ["nix-command" "flakes"]` —
subsequent rebuilds don't need the `--extra-experimental-features` flag.

This single command:
- Installs all packages (fish, zellij, zed, git, alacritty, niri, DMS…)
- Sets up home-manager (dotfiles, fish config, starship prompt, etc.)
- Enables greetd + niri-session (auto-login)
- Installs flatpaks (discord, spotify, easyeffects)
- Enables services (SSH, bluetooth, NetworkManager)
- Replaces nix.gc with nh clean

## 8. Post-Install Verification

```bash
# Verify system booted cleanly
systemctl --failed

# Check home-manager activation
ls -la ~/.config/git/config ~/.config/starship.toml

# Verify secrets are decrypted
ls -la /run/secrets/

# Check flatpaks
flatpak list

# Verify user shell (should be fish)
echo $SHELL
```

### 8.1 Set User Password

If you encrypted a password hash via sops and wired it in the config:
the password is set. If not, set it now:

```bash
sudo passwd flye
```

### 8.2 Add SSH Key to Authorized Keys

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

### 8.3 Verify DMS

DMS auto-starts via its systemd user service:

```bash
systemctl --user status dms.service
journalctl --user -u dms.service -f
```

If keybinds don't work or the launcher is missing, regenerate DMS config files:

```bash
dms setup
```

DMS files under `~/.config/niri/dms/` are auto-generated. The config ships
with pre-generated copies so they work on first boot, but if you change
DMS settings or add plugins, run `dms setup` to refresh them.

### 8.4 Install Additional Flatpaks

Edit `modules/features/flatpak/discord.nix` (or create new files) to add
apps, then:

```bash
sudo nixos-rebuild switch --flake .#<host>
```

## Troubleshooting

### `nix flake lock` fails with "experimental feature"

```bash
nix --extra-experimental-features 'nix-command flakes' flake lock
```

### `sops secrets/secrets.yaml` fails with "failed to parse input as Bech32"

Your `.sops.yaml` still has `age1_REPLACE_ME` placeholders. Replace
`&admin` with your real key (from `ssh-to-age < ~/.ssh/id_ed25519.pub`).

### `sops metadata not found`

The `secrets/secrets.yaml` placeholder is plaintext. Delete it first,
then `sops` will create a proper encrypted file:

```bash
rm secrets/secrets.yaml
sops secrets/secrets.yaml
```

### `sops updatekeys` fails with "failed to get the data key"

sops needs your **private** key to decrypt. Create the identity file:

```bash
mkdir -p ~/.config/sops/age
ssh-to-age -private-key -i ~/.ssh/id_ed25519 > ~/.config/sops/age/keys.txt
chmod 600 ~/.config/sops/age/keys.txt
```

### `path 'options.nix' does not exist`

The file uses relative imports from `modules/collections/core.nix` —
`../options.nix` should resolve correctly. If you moved files around,
check that `options.nix` is at `modules/options.nix` and that
`modules/collections/core.nix` references it as `../options.nix`.

### `option "home" does not exist` or `attribute "flye" already defined`

These were bugs in the DMS module that have been fixed. If they recur,
check that `modules/features/dms/default.nix` sets
`home-manager.users.${config.username}` exactly once with both
`.imports` and `.programs.dank-material-shell` nested inside it.

### `attributes pkgs missing`

A module is using `pkgs` in the outer (flake-parts) scope instead of the
inner (NixOS module) scope. All modules must follow the two-layer pattern:

```nix
{ self, inputs, ... }:                              # outer: flake-parts
{
  flake.nixosModules.<name> =
    { pkgs, config, ... }:                          # inner: NixOS module
    {
      environment.systemPackages = with pkgs; [ … ];
    };
}
```

### DMS doesn't start

```bash
systemctl --user status dms.service
journalctl --user -u dms.service -f
which dms
```

## Adding a New Host

1. Copy an existing host:
   ```bash
   cp -r modules/hosts/desktop modules/hosts/newhost
   ```

2. Update the three files — change every occurrence of `desktop` to
   `newhost` (including the registered module name in
   `hardware-configuration.nix`).

3. Replace `hardware-configuration.nix` with the real generated config
   wrapped per §3 above.

4. Add the host's SSH host key to `.sops.yaml` (see §5.5).

## Maintenance

```bash
nix flake update                 # update all inputs
sudo nixos-rebuild switch --flake .#<host>   # apply

nh clean all --keep 5            # clean old generations
sudo nix-collect-garbage -d      # or manual
```

Rollback: `sudo nixos-rebuild switch --rollback`

## Notes

- The niri config uses DMS for launcher, clipboard, notifications, etc.
  DMS auto-starts via systemd user service (`systemd.enable = true`).
- Timezone is `Europe/Stockholm` by default.
- SSH is enabled with key-only auth.
- Laptops use `nvidia-prime` (offload mode) instead of `nvidia` (desktop).
  The bus IDs in `modules/system/drivers/nvidia-prime.nix` need to be set
  per machine (`lspci | grep -E "VGA|3D"`).
